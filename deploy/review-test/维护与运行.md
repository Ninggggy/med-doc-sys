## 准备与启动

```sh

  --root /Users/ning/.cache/med-doc-review-product \
  --private /Users/ning/.cache/ocr-context-work/med-doc-sys-ocr-private \
  --business-python /Users/ning/.cache/ocr-context-business/bin/python \
  --node-bin /Users/ning/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin

/Users/ning/.cache/ocr-context-business/bin/python agent/deploy/start_review_test.py \
  --config /Users/ning/.cache/med-doc-review-product/test-runtime.json --port 5073
```

准备命令已经实际运行通过：全量读取 det/rec 各三份必需文件、导入同版本 OCR 依赖，90 秒超时明确失败；前端 `npm ci --offline` 严格沿用锁文件，再构建。没有模型下载动作。运行使用 `release/agent` 非同步目录；只复制所需原型核心，未复制已否定的视觉候选或评分/答案/人工草稿。

需复用本机已经验证的两个 Python 环境、Node/npm 本地缓存、官方权重缓存。OCR 依赖实测 PaddleOCR 3.7.0、Paddle 3.3.1、PaddleX 3.7.2、NumPy 2.3.5、PyMuPDF 1.28.2；没有整体升级。此说明不声称新机器无需准备这些依赖。

此版本无需账号或登录。修订时间仍由后端记录；修订人标为“未登录操作”，无法识别具体人员。不启用多 worker/reloader，否则会复制模型。

开发/测试开关：`FILING_PDF_BACKEND=ppocr_v6_medium`；`FILING_PADDLE_CODE/PRIVATE/RUNTIME` 均由测试启动器设置。默认解析配置仍为 existing；未修改生产配置文件。
