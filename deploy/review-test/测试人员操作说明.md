# 备案变更核对测试版：操作说明

本机入口：http://127.0.0.1:5073/#/filing-change-review 。直接打开即可，无需注册或登录。

1. **上传**：新增项目 → 进入审评。申请表在“申请表”页签上传 Word/PDF；其他材料在“申报资料”选择实际所属目录后上传，点击“解析”。PDF 使用本地 PP-OCRv6 medium；首次识别加载模型，随后复用同一模型。Word/文本复用原有解析器。
2. **查看与定位**：材料行点击“核对”，申请表点击“核对申请表原页”。左侧显示原页或 Word/文本原内容；右侧可选择待核问题，也可主动选择没有报警的正文行、单元格。只有真实区域/行坐标才高亮；Word 逻辑表格显示行列位置，不假装有逐字坐标。原图读取失败时不能保存确认。
3. **修订或确认**：选择“修改有效内容并保存”或“确认当前识别正确”；修改文字后重新勾选“已核对当前值”，填写简短核对依据。空白、未填写、仍无法辨认分别选择对应状态。问号/方框如果本就在原件里，需要明确勾选“属于原件正文”；若代表看不清，选择“仍无法辨认”。有表格结构或跨字段归属问题时使用已有完整区域/表格修订控件，不猜所属字段。
4. **保存与继续**：可每次只处理一项，其他待核问题保留。保存后刷新可继续。有效内容单独显示，原始识别与候选仍保留。保存失败会报错并保留草稿；来源或修订版本冲突时不要覆盖他人的新结果，应保留当前文字，重新读取后核对。修改后旧确认不会自动沿用。
5. **检查与审评**：点击“解析就绪检查 / 去核对”查看尚未解决的问题。补齐实际必需资料后，发起新审评，在“AI 审评结果”和“审评报告”查看结果及导出 Word。修订后旧报告会提示资料已变化；需新审评才能生成采用新内容的报告。能启动审评不代表结论通过，缺项和业务风险仍可能要求补正。

**测试边界**：这是本机单进程开发/测试部署，没有登录和个人身份识别；修订会标记为“未登录操作”，不能追溯具体人员。当前测试启动器关闭语言模型摘要，仍执行真实规则、有效材料读取、审评记录和报告接口。无需编辑 JSON、运行 Python、提供人工答案文件或寻找 OCR 实验目录。

自动 OCR 对印章/底纹、受遮挡正文、部分药名/限制词及斜杠仍可能出错；没有报警也可以主动修订。既有三份原件未代签、未批量确认，开发自动化测试通过不等于它们已经人工验收或自动全对。
