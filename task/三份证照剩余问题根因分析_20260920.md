# 三份证照剩余问题根因分析

本次只读检查最终同轮结果、当前代码及原始图像属性，并运行三个小型反例和一次实际裁剪像素比较；未修改生产代码、未重新运行整批OCR。结论：存在可复现的输入、对齐、补识别调度和候选采用问题，现在不能把失败归结为Tesseract能力上限。

## 已确认的问题

### 1. 相同像素重复消耗补识别名额

第二份第3页最后两次实际补识别，PDF坐标右边界分别为296.444458和296.524567，其余坐标相同。216 DPI实际渲染结果均为像素框 `(404,521,486,66)`，像素逐字节相同，触发类型均为 `ocr_quality`。当前 `pdf_page_extractor.py:940` 用浮点PDF裁剪框作为复用键，故同一输入用了两个请求。

通用修复：以实际渲染像素窗口、页面/变换、DPI、分段模式、预处理和遮罩状态组成普通元组键；以已经生成的输入窗口判定相同输入。只合并确实相同的输入，不能因IoU较高合并两个不同单元格。不新增hash机制，不把不同分段/图像变体混用。

### 2. 阅读顺序算法制造新旧假冲突

`pdf_scan_evidence.py:130` 按 `round(y/词高)` 排序，不是按文本行排序。实际反例：旧词AB；新词A在[0,20,45,30]、B在[55,20,100,40]，同一行从左到右应为AB，函数却输出B A并标为conflict。

通用修复：先按已确认版面块/单元格限制候选，再按基线和纵向重叠构造行；优先保留引擎原始行/词序，在同一行内按方向对齐。旧、新各自建立行序后进行允许分词不同的单调序列对齐。数值、单位、符号和限制词原样保留。

同一函数只做重叠连通分组：一个跨两格的新词框会把两格旧文字合并为一个比较区域。反例也已复现。因此不能只修排序；要同时加入单元格/栏边界约束。跨格词框应成为独立结构歧义，不能把整行旧层拉进同一个冲突框。

### 3. 文字优先级被大片墨迹错误继承

`pdf_page_extractor.py:948` 只要墨迹框与任一旧层冲突框相交，就提升到最高优先级，随后按面积排序。大块底纹、印章边缘和表线可能因为局部相交而再次抢占名额。第一份第2页实际唯一补识别覆盖整页且失败，其余131条记录为预算耗尽。第三份第3页4次实际补识别全部accepted_count=0，仍有210条区域上限记录。

通用修复：优先级依赖候选自身的形成依据及文字行/单元格支持，不能由“碰到一个冲突框”继承。先形成真实版面区域，再挂诊断；分开记录区域和它关联的多条诊断。根据文字证据、可处理缺口和预计成本安排四个实际裁剪；面积只作最后同级比较。边框、底纹、二维码保留分类及定位证据，印章不能整块清空。

### 4. 主识别全空时存在补识别无法启动的闭环

`pdf_page_extractor.py:1088` 要求补识别候选必须找到主结果/已采用结果中可比较的字高。已复现：确认的单元格内得到95置信的Readable候选，但主结果为空，候选仍因 `recovery_context_ambiguous` 被拒绝。候选置信度本身不应成为自动通过依据，但“必须先有正确主词”同样不是合理的必要条件。

通用修复：补上不依赖主OCR成功的证据路径，例如已确认单元格内的实际文字行、字形连通域和笔画位置支持；结合既有置信度、数值核验、唯一归属和独立复核要求决定采用。保留无支持图形的拒绝规则，不能简单删除保护或接受所有高置信候选。

当前主结果与局部结果不同也总是保留冲突；当前比较规则主要能淘汰错误旧层，不能普遍纠正错误主识别。下一步必须明确选择表：哪些情况有足够图像证据替换主值、哪些情况仍保持未核验；不得按字符多或分数高覆盖。

### 5. 实际源分辨率差异没有进入扫描复核策略

原始图像元数据：第二份第3页主扫描7018×4964像素，第三份第3页主扫描1011×729像素。二者最终主识别与所有实际补识别都为216 DPI。`scan_sampling_dpi` 主要处理UserUnit；普通尺度或存在绘制线段时直接回原DPI。`recovery_layout_blocks` 仅 `vector_only` 时使用300 DPI，扫描密集小字仍不会走该路径。

通用修复：用主扫描变换计算真实像素密度，结合检测到的文字高度判断是否丢失可用源细节。高分辨率来源的密集区域，在既有像素与时间预算内按需使用300 DPI；低分辨率来源仅能验证插值/局部对比度是否改善分割，不能把插值称为恢复原始细节。附加印章、多图层与裁剪框保持合成原页语义，不直接拿最大嵌入图替代原页。

### 6. 表格结构对主OCR帮助仍不足，分段模式选择也不准确

带旧层扫描页的 `raw_scan` 禁用原表格去线与表格块模式，统一以原灰度/整页模式识别。此举避免旧预处理损伤，但不保证表格和底纹中的小字能正确分割。第三份第3页最终主/补结果只有22个词，其中仅1个词含汉字；100格只有9格非空。主要失败已发生在识别阶段，不能靠填格算法把缺失文字变出来。

补识别中 `ocr_quality` 默认选择单行模式7，即使冲突框实际上含多行。应由图像检测到的行数和版面结构选择单行或段落模式；不能由诊断代码决定分段模式。

通用修复：以小型独立答案集测试原灰度、局部对比度、受保护的可见线中心抑制等有限输入方案；依据原图证据选择一次主识别输入，保留原图及变换。表格结构参与裁剪边界、模式和字高估计。严禁全页强去背景/去红章，也不能因为某变体字更多就采用。整表改模式6已失败，不能把这种简单替换当作解决方案。

## 执行顺序与判断边界

1. 先把确定性反例修成回归：同像素复用、混合字高行序、跨格候选隔离、主结果为空的恢复保护、多行质量区域分段。用内容和位置不同的合成样本、旋转/裁剪/尺度样本验证。
2. 补齐13页业务正文、字段、单元格的独立逐字预期。当前抽样仅能证伪，无法证明完整正确；预期只进入本地测试，不进入生产规则。
3. 在少量代表区域上分别验证采样、输入处理、分段、对齐与采用，记录引擎原始输出、解析后词、候选、拒绝原因和最终正文，找出错误首次产生的位置。对照实验单列，不冒充生产四区域预算内的一次运行。
4. 主识别、内部数值核验、补识别和CPU后处理分别计时。现有证据不能量化谁占去了多少时间；先测再优化。优化不能跳过数值复核，预算不足保持未核验。
5. 修复后同轮跑13页真实OCR，逐字段/逐格核验，再验证原件上传、保存刷新、提取和报告；最后复测1/2/4并发及队列/回收。英文合成样本通过不能替代中文证照通过。

关键约束：整页主识别若漏掉几十个单元格，4个局部区域不可能被当成逐格重做全部内容的额度。应先让一次主识别达到足够覆盖，四个区域只补少数例外；不能把几十格拼接、批处理或改称“主识别”绕过预算。如果完成这些明确修复后，同一可读裁剪在约束内仍持续失败，再开展经授权的本地引擎比较。当前不能承诺保持现有约束一定能使三份全文全部通过。
